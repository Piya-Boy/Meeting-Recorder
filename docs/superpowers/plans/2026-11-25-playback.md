# Playback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, this session). Steps use checkbox syntax.

**Goal:** The Recordings screen plays a real recording (mic + system mixed) with play / pause / seek, through the default output device.

**Architecture:** A pure `Mixer` over `WavReader`, a device-independent `Playback<S: Sink>` state machine, a playback thread behind `PlayerHandle`, a WASAPI `Sink`, and UI plus app wiring that follow the existing request pattern.

**Tech Stack:** Rust 2021, egui 0.31, `wasapi` 0.27 (existing), std threads/mpsc.

**Spec:** `docs/superpowers/specs/2026-11-25-playback-design.md`

## Global Constraints

- No new dependency. The UI thread never reads WAV files or calls the audio device.
- Tests never open an audio device, except the `#[ignore]` hardware test. Tests do not assert translated text; new UI strings get a Thai entry and a Thai-test key.
- Pause and Seek discard buffered audio and rewind by the discarded frames, so Resume loses no audio.
- Playing is refused while a recording is in progress; deleting the playing recording stops playback and waits for the files to close.
- `cargo fmt --check`, `cargo clippy --all-targets` (zero warnings), `cargo test` before each commit. Stage by explicit path. No Co-Authored-By lines.

## Review Focus

- A recording whose two tracks have different lengths plays to the end of the longer one; the shorter is silent after its end.
- A recording with only `system.wav`, or only `mic.wav`, plays; a folder with neither, a truncated or a non-16-bit WAV is an error, not noise.
- Loud tracks never wrap around: the sum is clamped.
- Pause then Resume continues at the same place; Seek while paused and while playing; Seek past the end; Play after Finished restarts.
- Deleting the playing recording succeeds (files are closed before the delete); closing the app while playing exits cleanly.
